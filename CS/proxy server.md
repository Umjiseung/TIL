# 포워드, 리버스 프록시?

**프록시**가 무엇일까?
프록시는 클라이언트가 자신(프록시)를 통해 다른 네트워크에 간접적으로 접속, 접근할 수 있게 하는 시스템입니다.
간단하게 서버와 서버 중간에서 중계기라고 보시면 됩니다. 사용하는 이유가 궁금할 수 있습니다. 그 이유는 보안상의 많은 이유가 있을 수도 있고 성능 또는 안전성을 향상시키기 위함이라고 볼 수 있습니다.

또한, 보안상의 이유가 있을 수도 있지만 성능도 빠질 수 없습니다. 개발자는 유저에게 빠른 서비스와 좋은 경험을 제공해주어야 됩니다. 그 점을 기억하여 프록시를 사용하면 중복 연산등을 프록시에서 대신 해준다면 빠른 속도와 서버에게도 부하가 줄어드는 효과를 보여줄 수 있습니다.

하지만 프록시의 종류는 두가지가 있습니다. 이것을 구분하는 기준은 네트워크상에서 어느 쪽에 위치해 있나, 어느 방향으로 데이터를 제공하는지로 나뉘게 됩니다.

# 포워드 프록시
포워드를 이해하면 리버스를 이해하기 더 좋을 것입니다.
포워드는 클라이언트 바로 뒤에 놓여 같은 내부망에 존재하는 클라이언트의 요청을 받아 네트워크를 통해 외부에 존재하는 서버에 대신 요청을 보내 데이터를 받아오면 클라이언트에게 응답합니다.

```
클라이언트 -> 프록시 -> 네트워크 -> 서버 -> 네트워크 -> 프록시 -> 클라이언트
```

## 장점
### 클라이언트 보안
만약 클라이언트가 접속하고 싶어하는 웹사이트를 접속하지 못하게 방지할 수 있다. 이런 점은 정부, 학교 등의 기관에서 인터넷 접속을 제한하기 위해 사용하는 것이다. 이런 것을 사용하고 싶다면 프록시 서버에 룰을 추가하여 접속을 막을 수 있다.

### 캐싱
웹 페이지에 접근하면 프록시 서버는 페이지의 정보를 캐싱한다. 그래서 해당 페이지를 접근하거나 다른 클라이언트가 요청을 하면 프록시 서버에 캐싱해둔 정보를 그대로 반환하여 서버 부하를 줄이게된다.

### 암호화
포워드 프록시 서버를 통과할 때 클라이언트의 요청은 암호화가 진행된다. 요청은 다른 서버를 통과할 때 꼭 필요한 정보만 갖게 되는데 클라이언트의 ip를 숨겨주는 보안을 보여준다. 이런 점때문에 서버에서 ip를 추적해도 프록시 덕분에 알기 힘들다.
왜냐? 그 ip는 프록시 서버의 ip일 것이기 때문이다.

# 리버스 프록시

리버스 프록시는 서버 앞에 놓이는 프록시이다.
그러면 클라이언트는 서버에게 요청하는 것이 아닌 프록시에게 요청을 보낸다. 그 다음 요청을 받은 프록시가 서버로 부터 데이터를 가져와 데이터를 가져오는 방식이다.

간단하게
```
Proxy -> (Data) -> Client // 포워드 (Response)

Proxy -> (Data) -> Server // 리버스 (Request)
```

사실 흐름만 보면 바로 서버로 요청을 보내는 게 효율적이라고 생각이 들 수도 있지만 이것도 보안의 영향이 크다.
기업의 네트워크 환경에는 DMZ(내부 네트워크/외부 네트워크 사이에 존재하는 구간)이 존재한다. 이 구간에 메일 서버, 웹 서버, FTP 서버 등 외부 서비스를 제공하는 서버가 존재한다.

WAS(Web Application Sever)를 DMZ에서 서비스해도 상관은 없지만 보안은 상관이 없지 않다.
DB서버와 연결되어 있어 해킹을 당하면 바로 DB까지 영향이 갈 수도 있다.

## 장점
### 로드 밸런싱
네이버와 구글 등 유명한 사이트는 하루에 예상할 수 없이 많이 접속한다. 이런 요청들을 서버 하나로 감당하기에는 말도 안되는 짓이다. 하지만 프록시를 두어 여러 서버에 요청을 분산한다면 과부화가 되지 않게 방지할 수 있다.

### 보안
리버스를 사용하게 되면 원래 서버의 ip를 노출시키지 않을 수 있다. 따라서 DDoS 와 같은 공격을 막을 수 있다.
